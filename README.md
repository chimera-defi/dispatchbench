# model-routing-bench

Which model and reasoning effort should a coding task be routed to? This repo measures six Claude Code and Codex CLI configs on 12 Python problems written after the models' training cutoff, plus 4 small repo tasks. For each config it records where pass rate drops, and what a passing answer costs in dollars and seconds.

It was run once, on 2026-10-22, for $1.76 of measured Claude spend and $2.10 of Codex usage priced at list rates. Every number below is regenerated by `make report` from the cached calls, with no model calls.

## Result

| config | pass@1 | 95% CI | median s | p90 s | $ per pass | $ kind |
|---|---|---|---|---|---|---|
| haiku-low | 95% (57/60) | 85–100% | 10.0 | 16.0 | 0.00112 | measured |
| haiku-medium | 98% (59/60) | 93–100% | 13.0 | 26.8 | 0.00149 | measured |
| sonnet-medium | 100% (60/60) | ≥95% | 10.1 | 18.1 | 0.01244 | measured |
| luna-low | 77% (46/60) | 53–95% | 7.2 | 11.6 | 0.00090 | proxy |
| luna-medium | 78% (47/60) | 57–97% | 8.2 | 11.8 | 0.00089 | proxy |
| sol61-medium | 97% (58/60) | 87–100% | 22.6 | 36.2 | 0.01499 | proxy |
| luna-low-bare (exploratory) | 73% (44/60) | 52–92% | 6.8 | 11.1 | 0.00080 | proxy |

Function track: 12 problems × 5 attempts per config. "$ per pass" is total spend divided by passing attempts. Claude dollars are the CLI's reported `total_cost_usd`; Codex dollars are token counts times list price ([results/prices.json](results/prices.json)). luna-low-bare is luna-low with the Codex harness stripped to its smallest prompt (see below). It was added after the main run, so it is labelled exploratory.

1. **haiku-low is the cheapest config that stays above 90%.** It passes 95% at $0.00112 per pass. luna-low is 20% cheaper per pass ($0.00090) and about 3 s faster at the median, but passes 18 points less often (paired difference +18.3 pts for haiku-low, 95% CI +1.7 to +38.3).
2. **Luna's misses cluster on three problems, and high effort fixes most of them.** luna-low and luna-medium together pass 2/10 attempts on p04 (L2), 6/10 on p11 (L6) and 0/10 on p12 (L6). At low and medium effort luna emits a mean of 0 and 7 reasoning tokens per call. Re-run at high effort on those three problems, it emits about 730 reasoning tokens and passes 13/15, against luna-medium's 3/15 (+67 pts, CI +40 to +93), for $0.017 in total at a 14.5 s median. These three problems were chosen because luna failed them, so 13/15 is an upper estimate of what high effort adds in general.
3. **Stripping the Codex harness cuts input tokens by 60% but does not make luna as accurate as Haiku.** Turning off tools, features, environment context and the stock system prompt takes luna's minimum input from 14,389 to 5,845 tokens. On the three pilot problems, stripped luna and haiku-low both pass 9/9, at $0.00030 and $0.00028 per call. On the full 12-problem ladder, stripped luna passes 73% against haiku-low's 95%: −21.7 pts, CI −43.3 to 0.0, so the interval's upper end touches zero. Stripping did not change luna's own accuracy (−3.3 pts against stock luna-low, CI −20 to +13). Stripped luna is cheaper per pass than haiku-low: $0.00080, or $0.00120 if no input were served from cache, against Haiku's measured $0.00112.
4. **The agentic tasks did not separate the configs.** All four configs passed every hidden test in 12 of 12 runs. What differs is cost per run: luna-low $0.0040, haiku-low $0.0051, sonnet-medium $0.054, sol61-medium $0.075, a 19× spread for the same outcome. sol61-medium also took 89 s at the median against 28 s for the other three.

A routing rule these numbers support: send to haiku-low by default. If a cheaper first try is wanted, send to luna-low and re-ask failures at luna-high. Do not read luna's 77% as a fixed property of the model; at low effort it barely reasons.

### Codex harness floor

Each trim level adds Codex CLI 0.163.0 config knobs to the one before. The probe is one call per level on a trivial problem, at low effort.

| model | stock harness | + no project docs | + no env/permission context | + tool features off | + one-line system prompt | + shell tools off |
|---|---|---|---|---|---|---|
| gpt-6-luna | 14,389 | 14,389 | 14,210 | 9,930 | 6,485 | 5,845 |
| gpt-5.6-terra | 14,201 | 14,197 | 14,020 | 9,469 | 5,928 | 5,288 |

About 1.3k of the remaining tokens are the user-level `~/.codex/AGENTS.md` on the host that ran this, which no flag turns off. A clean install would sit lower; I did not measure it, because doing so meant copying the CLI's login file into a temporary home. terra at the smallest prompt costs $0.0080 per call on the pilot problems, about 28× haiku-low, so it was not run on the full ladder.

## Method

The design was pre-registered in [PLAN.md](PLAN.md) and committed before the first model call. Changes made after that are listed at the end of that file, as numbered deviations.

**Configs.** Six base configs, each a CLI, a model and a reasoning effort:

| config | CLI | model | effort |
|---|---|---|---|
| haiku-low, haiku-medium | Claude Code | claude-haiku-5-5 | low, medium |
| sonnet-medium | Claude Code | claude-sonnet-5-5 | medium |
| luna-low, luna-medium | Codex CLI | gpt-6-luna | low, medium |
| sol61-medium | Codex CLI | gpt-6.1-sol | medium |

**Function track.** 12 problems on 6 rungs (L1–L6), two per rung. Each prompt asks for one Python function. Tools are off: Claude runs with `--tools ""`; Codex runs in a read-only sandbox and is told not to use tools. Every problem ships with:

- an efficient reference;
- an independently written brute force that must agree with the reference on 2,000 random small inputs;
- at least two planted wrong solutions (greedy, off-by-one, float rounding, too slow, a missed rule) that the checker must reject.

`make selftest` checks all three. Candidates run in a separate `python3 -I` process with a 2 GB memory cap. Large cases get max(2 s, 10 × the reference's time). Grading happens after generation, one problem at a time, so parallel model calls cannot cause false timeouts. The L6 problems were written after a calibration run showed three configs passing all of L1–L5 (PLAN.md, deviation 5).

**Agentic track.** 4 small repo tasks: add a feature, fix four bugs, add config interpolation, add a retry queue. Each has visible tests plus hidden tests that are copied in only after the agent exits. Both CLIs get shell and file-edit tools, and no user settings or MCP servers. A run passes when every hidden test passes. The harness also records whether the agent edited the original tests (none did) and whether it wrote the regression test the task asked for.

**Escalation.** Pre-registered rule: if a model's highest base effort passes 2/5 or fewer on a problem, the next effort level runs 5 attempts on that problem only. It fired once, for luna.

**Statistics.**

- pass@1 is the fraction of single attempts that pass, with no retries and no picking of the best answer.
- Intervals are 95% hierarchical bootstrap intervals, 10,000 resamples. Each resample draws problems, then attempts within each problem, so five attempts at one problem do not count as five independent data points ([Miller 2024](https://arxiv.org/abs/2411.00640)).
- When every attempt passes, the bootstrap interval collapses to 100–100%. The table then shows the exact one-sided 95% lower bound, 0.05^(1/n), which treats attempts as independent and is therefore optimistic.
- Differences between configs are paired on the same problems.
- The breaking point of a config is the lowest rung where it passes 40% or less.

**Cost.** Claude dollars are the CLI's measured `total_cost_usd`. Codex dollars are a proxy: input tokens not served from cache, cached input tokens and output tokens, each at its list price from the model's page on developers.openai.com (URLs and access date in [results/prices.json](results/prices.json)). Read them as what these tokens would cost on the API, not as an invoice.

**Reproducibility.** Every model call is cached under `cache/`, keyed by the SHA-256 of the config, CLI version, harness flags, prompt, problem and attempt number. Every grade is cached by problem hash and code hash.

```bash
make report
```

rebuilds every table, chart and number in this README from the cache. It makes no model calls and needs neither CLI installed. `make run` and `make agentic` call models only for keys that are not cached yet.

## Limitations

- **Small sample.** 12 problems and 4 agentic tasks, with 5 and 3 attempts. The intervals are wide; read them before the point estimates.
- **The breaking point is unstable at this size.** With 10 attempts per rung, two attempts move it. Stripped luna breaks at L2 (4/10) and stock luna at L6, yet stripped luna then scores 10/10 on L3. The rung order is my prior about difficulty, not a measurement, and the per-problem chart shows where it was wrong (for luna, p04 at L2 is harder than every problem except p12).
- **The agentic track hit a ceiling.** All 48 runs passed. It shows cost and latency differences, not capability differences.
- **Codex cost is a proxy**, and it depends on the provider's prompt cache. Identical prompts got between 0 and 4.9k cached tokens, which moves a Codex call's cost by up to 2×. The stripped-luna row gives a no-cache bound for that reason. Claude cost is measured, but it is the CLI's own accounting.
- **Harnesses are matched, not identical.** Codex cannot turn tools off on the function track; it gets a read-only sandbox and an instruction. Codex also injects the host's user-level `AGENTS.md` (about 1.3k tokens), so every Codex input count includes tokens a clean install would not have. Claude Code keeps its own default system prompt.
- **Latency is wall-clock through the CLI** on one host with up to 4 calls in flight. It includes CLI start-up and network time, and is not comparable to API time-to-first-token. The exploratory stripped-luna run used one lane at a different time of day, so its latency is not a clean comparison with luna-low.
- **The cache key leaves out a few inputs.** The effort and model literals inside the trim probe and the checker's source are not hashed. A changed one-line system prompt is caught by a content check instead.
- **One run in time.** Hosted models change. CLI versions and run dates are in [results/manifest.json](results/manifest.json); a later re-run may differ.

## Prior work this borrows from

- [LiveCodeBench](https://livecodebench.github.io/) ([Jain et al. 2024](https://arxiv.org/abs/2403.07974)): problems written after the models' training cutoff, to limit contamination.
- [SWE-bench](https://www.swebench.com/) ([Jimenez et al. 2023](https://arxiv.org/abs/2310.06770)) and [SWE-bench Verified](https://openai.com/index/introducing-swe-bench-verified/): grade repo tasks with tests the agent never sees, and check the tests themselves. Here that check is the brute-force agreement and the planted-bug rejection.
- [Adding Error Bars to Evals](https://arxiv.org/abs/2411.00640) (Miller 2024): clustered resampling when one question has several attempts, and paired comparisons between models.
- [METR, measuring long tasks](https://metr.org/blog/2025-03-19-measuring-ai-ability-to-complete-long-tasks/): describe a model by where its success rate drops, not by one average.
- [Aider leaderboards](https://aider.chat/docs/leaderboards/) and [Artificial Analysis](https://artificialanalysis.ai/): report cost and speed next to accuracy.
- [Hamel Husain on evals](https://hamel.dev/blog/posts/evals/): read the failures. The per-problem chart and the outcome counts are here for that reason.

## Layout

```
bench/            problems, prompts, runners, sandboxed grader
  problems/       12 problems: statement, reference, brute force, planted bugs
  agentic/        4 repo tasks (visible tests, hidden tests, reference solution) and their runner
  pilot/          the earlier pilot's prompts and problems, reused by the trim probe
  run.py          function-track runner (cache-first, 4 lanes max, $8 Claude cap)
  escalate.py     pre-registered escalation step
  trim_probe.py   Codex harness floor probe (exploratory)
analysis/         statistics, summary tables, SVG charts (standard library only)
cache/            cached model calls and grades; the source of every number
results/          graded rows (jsonl), prices, manifest, summary, report
PLAN.md           pre-registration and deviations
```

A full rewrite of the page generator is listed as undone if not reached.

## Method and gates
1. Tag `pre-shrink`, `ruling/f77c040`.
2. Phase A (dead run-side code): builder deletes; report-side imports (`PIDS`, `cost`, `visible`, `extract`, constants) move into the surviving module. Gate: golden rebuild clean + `make audit`.
3. Phase C first, same PR: tests.
4. Phase B (analysis generator rewrite under a byte-identical page) is a separate, later PR only if time remains; if not, it is listed as undone and does not hold the landing.
   Phase C: replace 32 test files with a few e2e (golden rebuild, audit, page guards for fonts/xfig/visible lines/self-contained, runtime JS decks), trim docs. `docs/landcheck_allow.json` entries for intentional removals.
5. Deleted-file links in SETUP.md, RAW_RUNS.md, results/README.md, PLAN.md repoint to `blob/b9fc17b/...`; generated RAW_RUNS lines changing is expected and gets a reason in `docs/landcheck_allow.json`.
6. Gates before PR: golden clean, `make audit`, pytest, `landcheck --base main` (acknowledged), Claude review (model named in PR). The repo has no CI workflow, so "green CI" is this gate.

## Migration and rollback
Land as one PR from `session/shrink-db-1108` into main with a merge commit (no rewrite). Deploy surface is only page.html, which stays byte-identical, so nothing live changes. Rollback: `git revert -m 1 <merge>` or check out tag `pre-shrink`. `shrink-1101` (74 local commits on an older pre-rewrite base 76de74d; main is 110 commits ahead of it; last commit 6 days ago) is superseded, not merged. Checked: its tip differs from main in 45 harness files (+2,291/-747) because it predates the Terra, Hetzner and priority-tier work now on main, and its own change is a page-content shrink ("one trade-off explorer and concise sections") that would drop page text the operator's regression reports required (see memory page-regression-guards). Merging it would need conflict resolution across the page generator and risk exactly those regressions. This plan keeps the page byte-identical and shrinks code under it. The branch stays untouched (someone's unlanded work) and is listed in the report. The ~20 sibling `dispatchbench-*` checkouts are listed, not touched.

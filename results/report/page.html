❓ How it was run

Every config faced the same new problems and hidden tests, with tools off (the model could not run code, read files or search).

📚 Problems by set (Easy/Medium/Hard)

Outside the pilot, LeetCode links are the closest analogues I found by hand; the problems were written for this bench. Pilot links are labelled source because those problems came from LeetCode. The Easy/Medium/Hard badge is a guess at the LeetCode difficulty; the rung (L1 to L7) is this bench's own order. They need not agree: p01 overlap_minutes (L1) is Medium, p06 calc (L3) is Hard, p08 recur (L4) is Medium.

  • Pilot: well-known LeetCode problems. Every config passed, so it ranked nothing and is not scored.
    • E Fizz Buzz source
    • M Course Schedule II source
    • H Candy source
    • H Reconstruct Itinerary source
    • H Minimum Window Substring source
    • H Wildcard Matching source
  • Main ladder: 12 new problems, p01–p12, rungs L1–L6 (2 per rung, rising difficulty). Every config ran it.
    • p01 overlap_minutes (L1) M
      like My Calendar III      minutes with at least k meetings at once; half-open intervals, sweep line
    • p02 squash (L1) E
      like String Compression      run-length encoding with escaped digits and backslashes
    • p03 ledger (L2) M
      like Simple Bank System      bank operations with validation rules, frozen accounts and transfers
    • p04 taller_within (L2) M
      like Count of Smaller Numbers After Self      count taller people among the k in front; sliding window
    • p05 pass_route (L3) M
      like Cheapest Flights Within K Stops      cheapest route when zone passes can be bought on the way; state-space shortest path
    • p06 calc (L3) H
      like Basic Calculator      integer expression parser: precedence, right-assoc power, unary minus, errors
    • p07 weighted_distance_sums (L4) H
      like Sum of Distances in Tree      weighted distance sums from every tree node; rerooting
    • p08 recur (L4) M
      no close LeetCode analogue      calendar recurrence rules (daily, weekly, monthly) expanded to dates
    • p09 k_machine_schedule (L5) H
      like Maximum Profit in Job Scheduling      best total pay for jobs on k printers; weighted interval scheduling
    • p10 avoid_count (L5) H
      like Find All Good Strings      count strings avoiding banned substrings; automaton DP, modulo
    • p11 best_average (L6) H
      like Maximum Average Subarray II      largest average of a subarray of length at least k, as an exact fraction
    • p12 sheet (L6) H
      like Design Excel Sum Formula      spreadsheet evaluator with references, ranges, division and cycle errors
  • L7 set: 3 extra-hard problems, p13–p15, rung L7. L7 has 3 problems, not 2, because it was added after every strong config passed L6 to look for a breaking point; it is scored separately from the main ladder.
    • p13 xor_ring (L7) H
      no close LeetCode analogue      XOR cellular automaton on a ring for huge t; doubling
    • p14 bounce_board (L7) H
      like Snakes and Ladders      expected turns on a bouncing board game with jumps, as an exact fraction
    • p15 paint_erase (L7) H
      like Range Module      paint and erase ranges where higher colours win; segment tree
  • Each config tries each problem 5 times, tools off.
  • The whole bench cost about $2.46 on Claude and an estimated $35.40 of Codex quota.
  • Sets:
    • Main ladder: 12 problems, 5 tries each. Total: 60 calls.
    • L7: 3 problems, 5 tries each. Total: 15 calls.
    • Luna-miss set: the 7 main-ladder problems luna-low missed most.
    • Chosen after the main run. Each row has 35 attempts.
    • Repo tasks: 4 edits, 3 tries each. Total: 12 calls.
  • Pass = every hidden test passes: the fixed cases, random cases checked against the reference solution, and large cases for speed.
  • Sample tests = the worked examples in the problem text. Cheap to run, and the model can see them.
  • Claude $ from the CLI. Codex $ = tokens × list price; ~ means estimated from tokens, not billed. 95% intervals from 10,000 bootstrap resamples (how much the pass rate would wobble on a rerun).
  • Run by Wren, a Claude Opus 5.5 orchestrator. It is not one of the configs tested.

Q: Does Claude's harness make Codex look bad?
A: Slightly, but below the 0.15 we set as the bias threshold. Codex's harness helped luna-low more than haiku-low: the gap between them changed by +0.133. The confidence interval excludes zero but stays below 0.15, so we do not call it bias.

We had Codex build its own harness: the program that sends the problem to the model and grades the answer. We ran luna-low and haiku-low on both harnesses (6 hard problems × 10 repeats).

The confidence interval is the range of bias the data support: +0.033 to +0.233. Bias here means a change in the gap between the models' pass rates.

The harnesses differ in mechanism: one-shot (answer once) vs tool loop (run code and revise), not just in who built them.

Codex built and ran its harness with 0 harness errors and no timeouts, in about 74 minutes of wall time for the recorded calls.

In the main benchmark, Codex answered through its own command-line app, with personal settings ignored and tools off. We also tried luna with Codex's own system prompt and tool instructions removed (the luna-*-bare rows) to see how much those instructions affected the results.

On repo tasks, instructions in the host's AGENTS.md file caused 57 of 97 sol61-medium shell commands and 26 of 62 luna-low commands. Those extra commands are included in Codex's measured time.

✅ CONCLUSION

Use sol61-high when Codex has quota. Use haiku-low when it does not; use haiku-high when a miss would be costly or you need speed.
  1. Codex has quota: sol61-high. Run the worked examples after; haiku-low fixes only if they fail ($0 Claude).
  2. Claude only (Codex out): haiku-low first. If its answer fails the problem's worked examples, or a wrong answer would be costly, use haiku-high instead.
  3. Need it faster than sol61-high (27.4 s)? haiku-high: 14.7 s, never missed, $0.0028 per pass.
  4. Must stay on Codex and need speed? sol61-high fast mode: 17.4 s, $0.036 per pass, about 1.9× the Codex usage.
  5. Fastest at any price? astra-medium fast mode: 9.9 s, $0.15 per pass.
  6. Want a bigger Claude model with zero misses? sonnet-medium: also never missed, 10.1 s, but 4.4× haiku-high's cost per pass.
  7. Best luna + Haiku pipeline: luna-high-bare → Haiku reviews every answer; passed 35/35, but cost 1.8× as much as haiku-medium alone.
  8. Never luna-low or luna-medium alone.

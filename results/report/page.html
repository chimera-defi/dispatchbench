      def squash(s: str) -> str:
      Compress a string by splitting it into maximal runs of the same character and writing each run as follows:

    • p03 ledger (L2)# M
      like Simple Bank System      bank operations with validation rules, frozen accounts and transfers
      Try it
      def ledger(ops: list[str]) -> tuple[dict[str, int], list[int]]:
      Process a list of bank operations, in order. Each operation is a string of tokens separated by single spaces. An account name is any token. An amount `N` is valid only if it consists entirely of the decimal digits 0-9, with no sign; leading zeros are allowed (`"007"` is 7).

Operations:
- `open A N`: create account `A` with balance `N`, where `N >= 0`. Fails if `A` already exists.
- `deposit A N`: add `N` to `A`. Requires `N > 0` and that `A` exists. Deposits are allowed while `A` is frozen.
- `withdraw A N`: subtract `N` from `A`. Requires `N > 0`, that `A` exists and is not frozen, and that its balance is at least `N`.
- `transfer A B N`: move `N` from `A` to `B`. Requires `N > 0`, `A != B`, both accounts exist, `A` is not frozen, and the balance of `A` is at least `N`. `B` may be frozen.
- `freeze A`: requires that `A` exists and is not frozen.
- `unfreeze A`: requires that `A` exists and is frozen.
- `undo`: reverts the most recent successful operation that has not already been reverted, ignoring `undo` operations themselves. Reverting `open` removes the account. Reverting `freeze` or `unfreeze` restores the previous frozen state. An `undo` with nothing left to revert fails. An `undo` can never itself be reverted.

Any operation that breaks a rule, has an unknown verb, has the wrong number of tokens, or has an invalid amount fails. A failed operation changes nothing.

Return a pair `(balances, rejected)`:
- `balances` maps every account that exists at the end to its balance.
- `rejected` is the ascending list of 0-based indices of the operations that failed.

Example: `ledger(["open a 10", "open b 0", "transfer a b 4", "freeze a", "deposit a 5", "withdraw a 1", "undo", "undo", "withdraw a 1", "undo", "undo", "undo", "undo", "undo"])` returns `({}, [5, 13])`. Index 5 fails because `a` is frozen. The undos at 6 and 7 revert the deposit and the freeze. Index 8 withdraws 1, and index 9 reverts it. Indices 10, 11 and 12 revert the transfer, `open b` and `open a`. Index 13 has nothing left to revert.

Constraints: `0 <= len(ops) <= 20000`.

    • p06 calc (L3)# H
      like Basic Calculator      integer expression parser: precedence, right-assoc power, unary minus, errors
      Try it
      def calc(expr: str) -> int | str:
      Evaluate an integer expression and return its value as a Python `int`, or the string `"error"`.

Syntax: non-negative decimal integer literals, binary operators `+ - * / % ^`, unary minus, parentheses, and any number of spaces between tokens. Every input is syntactically valid.

Precedence, from tightest to loosest:
1. `^` (power), right-associative: `2^3^2` is `2^(3^2)` = 512.
2. Unary minus, which may repeat (`--3` is 3). It binds looser than `^`, so `-2^2` is `-(2^2)` = -4. The right operand of `^` may start with a unary minus: `2^-1` is `2^(-1)`.
3. `*`, `/`, `%`, left-associative.
4. `+`, `-`, left-associative.

Semantics, with exact integer arithmetic and no size limit:
- `a / b` divides and truncates toward zero: `-7 / 2` is -3.
- `a % b` is `a - b * (a / b)`, using the truncating `/` above: `-7 % 2` is -1, and `7 % -2` is 1.
- `a ^ b` with `b >= 0` is `a` to the power `b`, and `0^0` is 1.
- The whole result is `"error"` if any evaluated step divides or takes a remainder by zero, or raises to a negative power.

Examples:
- `calc("1 + 2 * 3")` returns `7`.
- `calc("-2^2")` returns `-4`.
- `calc("(-2)^2")` returns `4`.
- `calc("2^3^2")` returns `512`.
- `calc("-7 / 2")` returns `-3`.
- `calc("7 % -2")` returns `1`.
- `calc("10^20 / 3")` returns `33333333333333333333`.
- `calc("5 / (3 - 3)")` returns `"error"`.
- `calc("2^-1")` returns `"error"`.

Constraints: `1 <= len(expr) <= 10000`. Parenthesis nesting depth is at most 50. In every test, exponents stay small enough that the exact result has at most a few thousand digits.

      Try it
      def recur(start: str, rule: str, count: int) -> list[str]:
      Expand a calendar recurrence rule. `start` is a date `YYYY-MM-DD`. Return the first `count` dates, in ascending order as `YYYY-MM-DD` strings, that are on or after `start` and match `rule`. `start` itself is included if it matches.

`rule` is one of the forms below. Tokens are separated by single spaces, and `K` is an integer of 1 or more.

- `DAILY K`: `start`, `start + K` days, `start + 2K` days, and so on.
- `WEEKLY K DAYS`: `DAYS` is a comma-separated list of distinct weekday codes from `MO TU WE TH FR SA SU`, in any order. Weeks run Monday to Sunday. Week 0 is the week that contains `start`. Only weeks 0, K, 2K, ... are active, and only the listed weekdays in them match.

- `MONTHLY K N WD`: the `N`-th weekday `WD` of each active month, where `N` is `1`..`5`, or `-1` for the last one. A month without a 5th such weekday contributes nothing.
- `YEARLY K MM-DD`: year 0 is the year of `start`. Only years 0, K, 2K, ... are active, each on month `MM`, day `DD`. If the date does not exist in an active year (`02-29` in a non-leap year), that year contributes nothing.

- `recur("2023-03-01", "YEARLY 1 02-29", 2)` returns `["2024-02-29", "2028-02-29"]`.

Constraints: `start` is between 1900-01-01 and 2400-12-31, and `1 <= count <= 50`. Every test has `count` matching dates before 3000-01-01.

    • p12 sheet (L6)# H
      like Design Excel Sum Formula      spreadsheet evaluator with references, ranges, division and cycle errors
      Try it
      def sheet(cells: dict[str, str]) -> dict[str, int | str]:
      Evaluate a small spreadsheet. `cells` maps cell names to contents. A cell name is one column letter `A`..`Z` followed by a row number `1`..`99` with no leading zero, for example `B12`. Return a dict mapping every name in `cells` to its value. A value is an integer, or one of the error strings `"#DIV/0!"` and `"#CYCLE!"`.

Contents:
- An integer literal such as `42` or `-7` is that integer.
- Otherwise the content starts with `=` and the rest is a formula. Spaces may appear between any two tokens.

Formula grammar, from lowest to highest precedence:
- `+` and `-`, left-associative;
- `*` and `/`, left-associative;
- unary minus (it may repeat, as in `--3`);
- atoms: a non-negative integer, a cell name, `( formula )`, a function call.

Functions:
- `SUM(...)`, `MIN(...)` and `MAX(...)` take one or more comma-separated arguments. Each argument is either a range `X1:Y2` (the rectangle with those two corners, in either order) or a formula.
- `IF(left OP right, then, else)`, where `OP` is one of `=`, `<>`, `<`, `<=`, `>`, `>=`, and `left`, `right`, `then`, `else` are formulas.

Semantics:
1. All arithmetic is on unbounded integers. `/` divides and truncates toward zero (`-7/2` is `-3`). Dividing by zero gives `#DIV/0!`.
2. A reference to a cell that is not in `cells` has value `0`.
3. Inside a range, cells that are not in `cells` are skipped. `MIN` and `MAX` with no values at all give `0`, and `SUM` with no values gives `0`. Formula arguments are never skipped: a formula argument that is a missing cell, such as `MIN(Z9)`, contributes `0`.
4. Errors propagate, and evaluation goes strictly left to right and stops at the first error. For a binary operator, if the left operand is an error the result is that error and the right operand is not evaluated; otherwise the right operand is evaluated next. Function arguments are evaluated left to right, and the cells of a range in row-major order: top row first, left to right within a row. The first error met is the result.
5. `IF` evaluates `left`, then `right`. If either is an error the result is that error. Otherwise only the chosen branch is evaluated. The other branch is never evaluated, so errors and references inside it have no effect.
6. A reference to a cell whose own evaluation is still in progress has value `#CYCLE!`. Each cell is evaluated at most once; once it has a value, later references reuse that value.

Examples:
- `sheet({"A1": "5", "A2": "=A1 * 2 + B9", "B1": "=-7/2"})` returns `{"A1": 5, "A2": 10, "B1": -3}`.
- `sheet({"A1": "=IF(A2 = 0, 1, A1)", "A2": "0"})` returns `{"A1": 1, "A2": 0}`.
- `sheet({"A1": "=A2 + B1", "A2": "=1/0", "B1": "=A1"})` returns `{"A1": "#DIV/0!", "A2": "#DIV/0!", "B1": "#DIV/0!"}`.
- `sheet({"A1": "=B1", "B1": "=A1 + 1", "C1": "=MAX(A1:B3, 2)"})` returns `{"A1": "#CYCLE!", "B1": "#CYCLE!", "C1": "#CYCLE!"}`.
- `sheet({"A1": "=MIN(B1:B3)", "B2": "4", "C1": "=MAX(D1:D5) + MIN(Z9)"})` returns `{"A1": 4, "B2": 4, "C1": 0}`.

Constraints: at most 2574 cells (every cell from `A1` to `Z99`). Every formula is valid and refers only to cells `A1`..`Z99`. A chain of references can pass through every cell. Cell names in ranges are always valid.

CONCLUSION#

Four configs passed every try in every set. They were haiku-high, sonnet-medium, sol61-high and astra-medium. Repo tasks counted as task complete: hidden and visible tests both pass. haiku-high is the cheapest, at $0.0028 per pass.
  1. With Codex quota left, send each task to sol61-high ⚡.
  2. Then run the sample tests. If one fails, haiku-low fixes it. Tested with plain sol61-high: 35/35 on the retest set, one run; sample tests are a weak gate. Haiku never ran.
  3. With Codex quota gone, use haiku-high. It is the cheapest config with no misses.
  • If speed matters most, use sonnet-medium. It takes 10.1 s to haiku-high's 14.7 s. sonnet-medium costs 4.4× as much per pass.
  • Don't use luna-low or luna-medium alone: they miss about 1 answer in 4.
  • luna-low passed 11 more on Codex's bench; haiku-low gained 3, near its ceiling. Bench and harness both differ, so the cause is not isolated. No pick changes.

How to read this data

Code quality columns

  • Complexity = cyclomatic complexity (branch count) of the most complex function, via radon.
  • Lint = ruff style warnings per solution.
  • Worse growth = time-growth exponent more than 0.3 above the reference's.
  • Time vs ref = run time divided by the reference solution's.
  • Mem vs ref = memory divided by the reference solution's.
  • Below 1.00 is faster or leaner.

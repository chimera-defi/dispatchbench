❓ How it was run

Every config (model + effort) got the same new problems and hidden tests. Tools were off: no code runs, file reads or search.

📚 Problems by round (Easy/Medium/Hard)
  • We wrote these problems for this bench.
  • Each LeetCode link is the closest analogue I found by hand.
  • Pilot links say "source": those problems come from LeetCode.
  • Easy/Medium/Hard is my guess at LeetCode difficulty.
  • Rungs follow this bench's own difficulty order.
  • The two can disagree:
    • p01 overlap_minutes (L1) is Medium.
    • p06 calc (L3) is Hard.
    • p08 recur (L4) is Medium.
  • Pilot: well-known LeetCode problems. Every config passed. It ranked nothing, so we exclude its scores.
    • E Fizz Buzz source
    • M Course Schedule II source
    • H Candy source
    • H Reconstruct Itinerary source
    • H Minimum Window Substring source
    • H Wildcard Matching source
  • Main ladder: 12 new problems.
    • Problem numbers: p01–p12.
    • Rungs: L1–L6, easiest first.
    • Each rung has 2 problems.
    • Every config ran it.
    • p01 overlap_minutes (L1) M
      like My Calendar III      minutes with at least k meetings at once; half-open intervals, sweep line
    • p02 squash (L1) E
      like String Compression      run-length encoding with escaped digits and backslashes
    • p03 ledger (L2) M
      like Simple Bank System      bank operations with validation rules, frozen accounts and transfers
    • p04 taller_within (L2) M
      like Count of Smaller Numbers After Self      count taller people among the k in front; sliding window
    • p05 pass_route (L3) M
      like Cheapest Flights Within K Stops      cheapest route when zone passes can be bought on the way; state-space shortest path
    • p06 calc (L3) H
      like Basic Calculator      integer expression parser: precedence, right-assoc power, unary minus, errors
    • p07 weighted_distance_sums (L4) H
      like Sum of Distances in Tree      weighted distance sums from every tree node; rerooting
    • p08 recur (L4) M
      no close LeetCode analogue      calendar recurrence rules (daily, weekly, monthly) expanded to dates
    • p09 k_machine_schedule (L5) H
      like Maximum Profit in Job Scheduling      best total pay for jobs on k printers; weighted interval scheduling
    • p10 avoid_count (L5) H
      like Find All Good Strings      count strings avoiding banned substrings; automaton DP, modulo
    • p11 best_average (L6) H
      like Maximum Average Subarray II      largest average of a subarray of length at least k, as an exact fraction
    • p12 sheet (L6) H
      like Design Excel Sum Formula      spreadsheet evaluator with references, ranges, division and cycle errors
  • L7 set: extra-hard problems.
    • Problem numbers: p13–p15.
    • Every strong config passed L6. We added L7 to find a breaking point. It has 3 problems instead of the usual 2. We score it separately.
    • p13 xor_ring (L7) H
      no close LeetCode analogue      XOR cellular automaton on a ring for t ≤ 10^18; doubling
    • p14 bounce_board (L7) H
      like Snakes and Ladders      expected turns on a bouncing board game with jumps, as an exact fraction
    • p15 paint_erase (L7) H
      like Range Module      paint and erase ranges where higher colours win; segment tree
  • Each config tries each problem 5 times, tools off.
  • The bench cost $2.46 on Claude. Codex quota use is estimated at $35.40.
  • These totals leave out the pilot, harness-bias, trim and luna-miss set pipeline runs.
  • Sets:
    • main ladder: 12 problems, 5 tries each. Total: 60 calls.
    • L7 set: 3 problems, 5 tries each. Total: 15 calls.
    • Luna-miss set: the 7 main-ladder problems luna-low missed most, chosen after the main run. Each config tried 7 problems, 5 times each. Each config made 35 calls.
    • Repo tasks: 4 edits, 3 tries each. Total: 12 calls.
  • Pass = every hidden test passes:
    • Fixed cases.
    • Random cases checked against the reference solution.
    • Large cases for speed.
  • Sample tests = the worked examples in the problem text. The model can see them.
  • They are cheap to run.
  • Claude $: what the CLI reports.
  • Codex $: tokens × list price. ~ marks estimates, not bills.
  • 95% intervals from 10,000 bootstrap resamples: how much a rerun's pass rate could vary.
  • Run by Wren, a Claude Opus 5.5 orchestrator. It is not one of the configs tested.
